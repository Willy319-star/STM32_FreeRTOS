# 自定义串口/CAN 协议清单

## 推荐帧结构

| 字段 | 建议 |
|---|---|
| 帧头 | 2 字节，降低误匹配概率 |
| 版本 | 支持兼容演进 |
| 消息类型 | 区分数据、命令、心跳、ACK/NACK |
| 序列号 | 请求响应匹配、重复帧检测 |
| 长度 | 可变负载边界 |
| 时间戳 | 数据采样或发送时刻 |
| Payload | 显式序列化 |
| CRC | CRC8/16/32，明确参数 |

## 必须定义的行为

- 字节序
- 整数与浮点编码
- 最大负载
- 非法长度
- 未知命令
- CRC 错误
- 接收超时
- 重复序列号
- ACK/NACK
- 重传次数和退避
- 版本不兼容
- 链路重置

## 接收架构

推荐：

DMA/中断
-> 环形缓冲区
-> 通知解析任务
-> 状态机
-> 完整帧校验
-> 消息分发

不要在 ISR 中完成复杂解析。

## 状态机要求

- 可从任意噪声位置重新同步。
- 在帧头第二字节错误时考虑是否可复用当前字节。
- 长度超过上限立即拒绝。
- 超时清除不完整帧。
- CRC 错误后继续搜索下一帧。
- 支持一批输入包含多帧。
- 支持一帧被拆成任意分片。

## 不直接发送结构体的原因

- padding 和 alignment
- 大小端
- 编译器 ABI
- float 表示和兼容性
- 协议升级困难
- 潜在未初始化填充字节

## 必做测试

- 正常帧
- 空负载
- 最大负载
- 半包
- 逐字节输入
- 连续多帧
- 前置噪声
- 帧内丢字节
- CRC 错误
- 超长长度
- 重复序列号
- 未知命令
- 超时
- 高速输入导致缓冲区接近满

## 面试追问

- UART 是否存在 TCP 意义上的“粘包”？
- 如何从错位中恢复？
- 为什么要有长度字段？
- CRC 能否纠错或加密？
- DMA + IDLE 的边界条件是什么？
- 如何避免环形缓冲区读写竞态？
