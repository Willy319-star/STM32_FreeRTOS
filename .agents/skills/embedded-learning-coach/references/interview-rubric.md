# 嵌入式面试评分量表

每项 0-5 分。

## 1. 技术准确性

- 0：核心概念错误
- 1：只能背定义
- 2：能解释基本 API
- 3：能结合项目说明
- 4：能处理边界与异常
- 5：能从底层机制和取舍分析

## 2. 项目所有权

- 0：无法说明自己做了什么
- 1：只会复述项目介绍
- 2：能说明任务
- 3：能说明设计与代码
- 4：能说明关键决策和证据
- 5：能说明系统演进和替代方案

## 3. 调试能力

- 0：只会重启或试错
- 1：无排查顺序
- 2：会使用基础日志
- 3：能提出假设和实验
- 4：能选择高信息量实验
- 5：能跨硬件、内核、系统、网络分层定位

## 4. 设计推理

- 0：无法解释选择
- 1：理由是“网上这么写”
- 2：知道优缺点
- 3：结合约束做选择
- 4：量化资源与性能
- 5：明确边界、失效模式和扩展策略

## 5. 表达沟通

- 0：无结构
- 1：堆砌名词
- 2：基本清楚
- 3：背景—方案—结果完整
- 4：准确区分事实和推测
- 5：能根据追问快速调整深度

## 6. 追问深度

- 0：第一问即无法回答
- 1：只能回答一层
- 2：两层追问后失去逻辑
- 3：能回答实现和原理
- 4：能回答故障和取舍
- 5：能主动提出测试和改进

## 总分解释

- 0-10：不适合在简历写“熟悉”
- 11-18：了解，需补实践
- 19-24：基本熟悉，可投递但需继续复盘
- 25-30：较扎实，能够承受大厂多轮追问

## 面试结束报告

- 总分及分项
- 三个最强点
- 三个最大风险
- 回答中无证据的声明
- 需要完成的实验
- 下一次模拟面试题目范围
