# FreeRTOS 实践与审查清单

## 任务设计

每个任务必须明确：

- 名称与职责
- 优先级及依据
- 周期或触发事件
- 最坏执行时间
- 阻塞点
- 栈大小与高水位
- 使用的共享资源
- 退出/重启策略

## 调度实验

至少完成：

1. 高优先级任务抢占低优先级任务。
2. 同优先级任务时间片轮转。
3. 高优先级任务不阻塞导致饥饿。
4. `vTaskDelay` 与 `vTaskDelayUntil` 周期漂移比较。
5. GPIO 翻转或 trace 测量任务周期和抖动。

## Queue

检查：

- 元素大小和队列长度是否依据生产/消费速率设计。
- 是否错误传递栈上对象指针。
- 满队列策略：阻塞、丢新、丢旧或覆盖。
- 大块数据是否使用内存池/指针并明确所有权。
- ISR 是否使用 `FromISR` 版本。
- 是否记录队列高水位和丢弃数量。

## Semaphore、Mutex、Notification

- 二值信号量用于事件同步。
- Mutex 用于共享资源互斥，并有所有者和优先级继承。
- Task Notification 适合一对一、轻量事件或计数。
- 设计优先级反转复现实验。
- 明确锁顺序，避免死锁。
- 不允许 ISR 获取 Mutex。

## 软件定时器

- 回调应短小、不可长时间阻塞。
- 回调通常只设置标志或通知任务。
- 检查 Timer Service Task 优先级和命令队列长度。
- 区分硬件定时器、中断、任务延时和软件定时器。

## ISR

- ISR 中只完成必要工作。
- 使用正确的 `FromISR` API。
- 处理 `xHigherPriorityTaskWoken` 和必要的 yield。
- 核实 Cortex-M 中断优先级配置。
- 解释为什么 `volatile` 不能替代同步原语。

## 内存与可靠性

- 启用栈溢出检测。
- 定期记录 `uxTaskGetStackHighWaterMark`。
- 解释使用的 heap 实现。
- 避免运行期不可控的动态内存。
- 检查 Watchdog 喂狗责任和失效场景。

## 面试追问

- 任务有哪些状态？
- 抢占和时间片的条件是什么？
- Mutex 与二值信号量的本质区别是什么？
- 优先级继承能否彻底解决优先级反转？
- 任务通知和 Queue 如何选择？
- ISR 为什么必须短？
- Tick 频率如何影响开销和时间精度？
- 删除任务后资源何时释放？
