# Potentiometer ADC stage

## 功能目标

本阶段加入旋钮电位器输入，用 STM32F407 的 ADC1 channel 0 采集 PA0 上的模拟电压。

接线：

- 电位器一端：3.3V
- 电位器另一端：GND
- 电位器中间滑动端：PA0 / ADC1_IN0

注意：PA0 是 3.3V 模拟输入，不能接 5V。

## 数据流

```text
TaskPotentiometer
  -> BSP_ADC1_PA0_Read()
  -> raw 0..4095
  -> percent 0..100
  -> xQueueSend(AppMessage)
  -> TaskSensorLog
  -> UART
```

## 为什么用轮询 ADC，而不是 DMA

方案 A：ADC + DMA

优点：

- 适合高频连续采样。
- CPU 占用低。
- 适合音频、波形采集、多通道连续采样。

缺点：

- 配置复杂。
- 需要 DMA buffer、半满/满中断或任务通知。
- 当前阶段调试成本更高。

方案 B：FreeRTOS 任务周期轮询 ADC

优点：

- 实现简单。
- 每次采样路径清晰。
- 适合旋钮这类低速输入。
- 串口日志容易验证。

缺点：

- 不适合很高采样率。
- 每次采样会占用一点 CPU 时间。

当前选择：

本项目当前只需要观察旋钮位置，并计划后续用它调节阈值或页面，所以选择任务周期轮询 ADC。采样周期设置为 500ms，足够用于人手旋钮输入。

## 为什么通过 Queue 发给日志任务

电位器任务只负责采样，不直接打印 UART。这样做有三个好处：

- 任务职责清楚：采样任务只采样，日志任务只输出。
- UART 是共享资源，集中输出更稳定。
- 所有传感器都走统一 `AppMessage`，系统结构一致。

## 测试方法

正常测试：

1. 上电后观察：

```text
POT init: ADC1_IN0=PA0 period=500ms
```

2. 转动旋钮，观察：

```text
POT OK tick=... raw=... percent=...% status=ok
```

预期：

- raw 接近 0 时，percent 接近 0%。
- raw 接近 4095 时，percent 接近 100%。
- 中间位置大约 40% 到 60%。

异常测试：

- PA0 悬空时，数值可能跳动，这是正常的模拟输入悬空现象。
- PA0 接 GND，raw 应接近 0。
- PA0 接 3.3V，raw 应接近 4095。

并发测试：

观察 DHT11、MPU6050、VL53L0X、POT、HEARTBEAT 是否都持续输出。如果 heap 稳定、任务都继续运行，说明新增 ADC 任务没有破坏 FreeRTOS 调度。

## 面试回答版本

问题：为什么这个旋钮电位器模块不用 DMA？

30 秒回答：

因为电位器是低速人工输入，500ms 采样一次就足够，不需要高频连续采样。当前阶段我选择 FreeRTOS 任务周期轮询 ADC，优点是实现简单、数据路径清晰、方便串口验证。DMA 更适合音频、波形或多通道高速采样，当前使用 DMA 会增加复杂度但收益不明显。
