# FreeRTOS observable framework

## 技术原理

FreeRTOS 启动后由调度器按照任务优先级和阻塞状态调度任务运行。
本阶段使用两个周期任务验证调度器是否正常工作：

- `TaskHeartbeat`: 每 1 秒输出 tick 和 heap。
- `TaskWorker`: 每 3 秒输出一次 alive 日志。

UART 是共享输出资源，因此使用 mutex 保护串口打印，避免后续多个任务同时
输出时日志交叉。

## 为什么使用

项目后续会接入 DHT11、MPU6050、VL53L0X、ST7735S TFT 和 ADC 旋钮。如果一开始
没有稳定日志系统，传感器异常、任务异常、时钟异常和串口异常会混在一起。

先建立可观测框架，可以先回答三个问题：

1. MCU 是否启动到 `main`。
2. FreeRTOS 调度器是否已经运行。
3. heap 是否稳定，任务是否按周期执行。

## 高频面试题

### 问题：为什么项目第一步不是直接接传感器？

30 秒回答：

我先建立了 FreeRTOS 最小可观测框架，通过 USART1 输出启动日志，并创建
周期任务打印 tick 和 heap。这样后续每接入一个传感器，都能先确认系统、
调度器和串口链路是正常的，避免把硬件问题和 RTOS 问题混在一起。

深入解释：

嵌入式项目调试经常会遇到程序没启动、任务没调度、外设没响应、串口没输出
等问题。如果没有统一日志，定位会很慢。Heartbeat 任务可以证明调度器正在
运行；heap 输出可以观察动态内存是否稳定；Worker 任务可以证明多个任务在
调度器下并发运行。

项目结合：

当前项目的入口是 `main.c`，可观测模块在 `app_observe.c`。`main` 初始化板级
时钟和 USART1 后调用 `AppObserve_Start()` 创建任务，然后启动调度器。

追问：

## 测试设计

正常测试：

- 打开 USART1，115200 8N1。
- 按复位键。
- 观察启动日志、`HEARTBEAT` 每 1 秒输出、`WORKER alive` 每 3 秒输出。

边界测试：

- 连续运行 5 分钟，观察 heap 是否持续下降。
- 快速多次复位，观察启动日志是否每次完整出现。

异常测试：

- 断开串口接收线，只保留板子运行，确认固件不依赖上位机输入。
- 临时减小 FreeRTOS heap，观察任务创建失败是否进入错误处理。

性能测试：

- 记录 heartbeat tick 差值，确认接近 1000 tick。
- 记录 worker tick 差值，确认接近 3000 tick。
